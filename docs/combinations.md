# نمونه‌های ترکیبی به ترتیب کار در پروژه

[English](combinations.en.md) · [راهنمای تک‌اسکیل‌ها](skills.md)

ترکیب‌ها یک workflow ترتیبی در همان agent هستند؛ به سرویس، ارسال پیام بین agentها یا اجرای موازی خودکار نیاز ندارند. هر skill فقط هنگام مرحلهٔ خودش خوانده می‌شود. هماهنگ‌کننده یک فهرست یافته‌ها نگه می‌دارد؛ گزارش‌های کامل قبلی دوباره تولید نمی‌شوند.

## قرارداد انتقال

برای هر یافته: `ID | severity | evidence-class | path:line | trigger/impact | status | verification`.
خلاصهٔ دامنه، checks اجراشده/نتیجه و محدودیت‌ها نیز منتقل می‌شود. محل و نتیجهٔ تست پس از تغییر کد دوباره بررسی می‌شود؛ شواهد قدیمی به‌تنهایی اثبات رفع نیست. اصلاح، فایل‌های docs و نتایج readiness ممکن است بررسی‌های قبلی را نامعتبر کنند.

نقش‌ها: enterprise-audit/security-audit/pr-review کشف؛ test-gap-analysis طراحی تست؛ audit-remediation اصلاح؛ audit-fix-loop تنها مالک تکرار؛ project-docs مستندسازی رفتار نهایی؛ release-readiness اعتبارسنجی نهایی. تمام skillها الزامی نیستند. audit-remediation زیر audit-fix-loop مرحلهٔ اصلاح است، نه یک حلقهٔ دوم.

## تعریف و ساخت پروژهٔ جدید

<div dir="ltr" align="left">

```text
پروژهٔ باز در همین محیط هدف است؛ root، دستورالعمل‌ها، stack، فایل‌ها، گزارش و checks مرتبط را از محیط کشف کن.
قبل از کار، وضعیت همان task را از قرارداد موجود یا .ai-work/INDEX.md و .ai-work/tasks/<task-id>/STATE.md بخوان.
تصمیم‌ها، اقدامات مهم، فایل‌ها، نتایج واقعی checks و قدم بعدی را در STATE.md و JOURNAL.md همان task ثبت و به‌روز کن.
پس از وقفه وضعیت ذخیره‌شده را با کد فعلی تطبیق بده؛ secrets ثبت نکن. اگر نوشتن ممنوع/ناممکن بود handoff متنی بده.
با task-orchestrator مراحل project-builder → project-docs را برای موضوع مورد درخواست در پروژهٔ باز هماهنگ کن.
نیازمندی‌ها را روشن، دامنهٔ توافق‌شده را پیاده و معیارهای پذیرش را بررسی کن.
مستندات جدید fa/en باشند؛ زبان اضافی: [locale اختیاری]. ترجمه‌های موجود هماهنگ شوند.
جهت و تراز مطابق زبان باشد؛ deployment انجام نده.
```

</div>

خروجی: پروژهٔ قابل اجرا، وضعیت نیازمندی به تست و مستندات هماهنگ؛ readiness فقط در صورت درخواست ارزیابی بسته اضافه شود.

## ترکیب دلخواه و بودجه

برای پروژهٔ جدید، معمولاً `project-builder → project-docs → release-readiness` کافی است؛ review و حلقهٔ اصلاح فقط در مراحل مرتبط اضافه شوند. [راهنمای ساخت پروژه](project-builder.md) نمونهٔ کامل تعامل دارد. برای پروژهٔ موجودی که فقط ممیزی می‌خواهد، مرحلهٔ ساخت را حذف کنید.
